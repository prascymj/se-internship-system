# ระบบจัดการการฝึกงาน — เอกสารประกอบ

🇬🇧 **[Read in English](../)**

ชุดเอกสารความต้องการและการออกแบบซอฟต์แวร์สำหรับ **ระบบจัดการการฝึกงาน (Internship Management System)** ที่พัฒนาขึ้นเพื่อสนับสนุนและติดตามกระบวนการฝึกงานของนักศึกษา **มหาวิทยาลัยพะเยา**

เว็บนี้รวบรวมเอกสารภาษาไทยเพื่อให้นักศึกษาเข้าใจกระบวนการฝึกงาน บทบาทผู้เกี่ยวข้อง และวิธีที่ระบบดูแลแต่ละขั้นตอน

> ระบบนี้ทำงานร่วมกับ **ระบบ internship หลักที่มีอยู่แล้ว** (ที่นักศึกษาบันทึก task ประจำวันและสถานประกอบการเข้าไปดู) โดยเน้นกระบวนการรอบข้าง ได้แก่ การเสนอสถานประกอบการ การนำเสนอต่ออาจารย์ การตรวจคุณสมบัติ การจัดการเอกสาร การนิเทศ และเอกสารหลังฝึกงาน

---

## ภาพรวมกระบวนการฝึกงาน

1. **ติดตามสถานะ** — นักศึกษาเห็นขั้นตอนปัจจุบันของตนเองในกระบวนการฝึกงานรายภาคการศึกษา
2. **เสนอสถานประกอบการและนำเสนอ** — นักศึกษาเสนอบริษัทและนัดนำเสนอกับอาจารย์ที่ปรึกษา ถ้าไม่ผ่านให้หาบริษัทใหม่และนำเสนอใหม่
3. **ตรวจคุณสมบัติการอบรม** — นักศึกษาต้องเข้าอบรมครบตามจำนวนที่กำหนดและอัปโหลด certificate ทุกครั้ง
4. **อัปโหลดเอกสารตอบรับ** — 3 ฉบับ: หนังสือขอความอนุเคราะห์ หนังสือตอบรับ และใบส่งตัว
5. **นิเทศ (3 เดือน)** — นักศึกษาปักหมุดสถานประกอบการบน Google Map; เจ้าหน้าที่มอบหมายอาจารย์นิเทศ 1 ท่านต่อบริษัทตามกลุ่มเส้นทาง; นิเทศได้ทั้งแบบ **online หรือ onsite**; ให้คะแนนตามแบบฟอร์ม/rubric และแบบสัมภาษณ์
6. **ยืนยันกับระบบหลัก** — นักศึกษายืนยันว่าได้บันทึก task ในระบบ internship หลักแล้ว
7. **สิ้นสุด & หนังสือขอบคุณ** — เมื่อจบการฝึกงาน ระบบสร้างหนังสือขอบคุณสถานประกอบการ และเมื่อบันทึกว่าสถานประกอบการประเมินผลนักศึกษาเสร็จแล้ว ระบบแจ้งเตือนนักศึกษา
8. **กรณีปัญหา** — หากถูกส่งตัวกลับระหว่างฝึกงาน ระบบบันทึกไว้และให้หาที่ฝึกใหม่; กรณีเกือบไม่ผ่านมีการบันทึกการดำเนินการ

## สารบัญเอกสาร

### ความต้องการ (Requirements)
- **[เอกสารข้อกำหนดความต้องการ](requirements/spec.md)** — ความต้องการเชิงฟังก์ชัน (FR) และไม่ใช่เชิงฟังก์ชัน (NFR) ทั้งหมด พร้อมแบบฟอร์มให้คะแนนนิเทศ rubric และคำถามสัมภาษณ์ในภาคผนวก
- **[Backlog](requirements/backlog.md)** — สรุป FR/NFR ทั้งหมดตามระดับความสำคัญ

### การออกแบบ (Design)
- **[รายการฟีเจอร์](design/feature-list.md)** — จัดกลุ่มความต้องการเป็นฟีเจอร์พร้อมระดับ MoSCoW
- **[User Journey](design/user-journey.md)** — flow การใช้งานตามบทบาท (นักศึกษา, อาจารย์ที่ปรึกษา, เจ้าหน้าที่ประสานงานฝึกงาน, อาจารย์นิเทศ) พร้อมแผนภาพ

### การทดสอบ (Testing)
- **[แผนการทดสอบ](testing/test-plan.md)** — กลยุทธ์ ขอบเขต และเกณฑ์ entry/exit
- **[เกณฑ์ยอมรับ](testing/acceptance-criteria.md)** — Given-When-Then ต่อทุกความต้องการ
- **[Test Cases](testing/test-cases/)** — test case แบบ step-by-step ต่อฟีเจอร์

## บทบาทผู้ใช้

| บทบาท | หน้าที่ |
|---|---|
| **นักศึกษา** | เสนอบริษัท อัปโหลดเอกสาร ปักหมุดตำแหน่ง ยืนยันการบันทึก task |
| **อาจารย์ที่ปรึกษา** | พิจารณาอนุมัติการนำเสนอสถานประกอบการ |
| **เจ้าหน้าที่ประสานงานฝึกงาน** | ตรวจคุณสมบัติ/เอกสาร มอบหมายอาจารย์นิเทศ สร้างหนังสือ จัดการกรณีปัญหา |
| **อาจารย์นิเทศ** | นิเทศ (online/onsite) และให้คะแนนนักศึกษา (1 ท่านต่อบริษัท) |

---

*ต้นฉบับภาษาไทยเป็นแหล่งอ้างอิงหลัก รหัสความต้องการ (FR-xx / NFR-xx) ใช้ตรงกันทั้งฉบับไทยและอังกฤษเพื่อการ traceability*
